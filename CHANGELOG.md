All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Any-depth candidate tree: `/branch` and `Ctrl+B`.** Candidate switching is no longer limited to the last turn. The new `/branch` command (also `Ctrl+B` from both pages) opens a candidate-tree panel that renders every fork at every depth — including branches inside inactive candidates — with tree navigation (`↑/↓` move, `←/→` fold/unfold), inline excerpts, per-candidate file-state hints (`files` / `no file state` / `files degraded`), and continuation counts. `Enter` on a candidate opens a confirm step with a read-only file preview (changed files, `+/-` line counts, taint and missing-bundle warnings) before switching both conversation and disk; `r` on a fork row regenerates that turn. Switching executes through the shared candidate-switch kernel: files move before the selection marker, the marker keys its fork point on the target leaf's owning turn so the inline `< n/m >` switcher re-arms at the switched-to depth, and the same busy/SubAgent guards apply. The panel follows the `/rewind` bottom-surface modal pattern and never touches the disk before the confirm step.

- **Full-manifest candidate file bundles.** `candidate-file-state` bundles are now version-2 full manifests of everything on disk under the project content roots (content-addressed, deduplicated), replacing the partial captures that only covered the fork turn's ledger-tracked paths. Switching to a candidate makes the disk strictly equal to its manifest: entries restore and on-disk paths outside the manifest are deleted, exempting symlinks and special files (recorded as `untracked` and surfaced in the switch outcome), while the scratch root `tmp/` stays outside manifests as before. Capture no longer derives its domain from the fork turn's checkpoint ledger (the ledger still anchors capture trustworthiness), and a read-only switch preview shares the exact deletion/restore computation with the switch itself.

- **Unified turn-focus cursor on `Alt+↑/↓`.** `Alt+↑/↓` now moves a turn-level focus cursor across every transcript, not just Stage-engine messages: it stops at each authored turn's prompt and final reply, wraps at the edges, highlights both messages in the brand color, and scrolls them into view. Stage behavior is preserved: the focused turn's eligible Stage message stays the target of `Ctrl+Alt+S` and mouse toggling. `Alt+←/→` still cycles candidates when the inline switcher is armed; otherwise it now reports guidance (`Ctrl+B` opens the candidate tree when the focused turn has candidates, `Ctrl+R` regenerates otherwise) instead of being swallowed silently — including on the Workspace page and hero, fixing the long-standing dead-key defect.

- **Horizontal candidate branching with `Ctrl+R` on Chat.** A turn can now be re-run as a new candidate while the old reply is kept, and the candidates are switchable in place. `Ctrl+R` re-runs the last turn — the whole turn, so on the chat-only Stage engine it is a single model call, while file-writing authoring engines re-run the full workflow — and appends a sibling candidate subtree off the shared user record; the old candidate stays in the append-only transcript but is cleared from the screen while the new candidate streams in its place, matching the regenerate semantics. The page-scoped binding leaves Workspace's existing `Ctrl+R` file reload unchanged and uses a control sequence available in traditional VT terminals across Windows, macOS, and Linux. After a regenerate, an inline `< n/m >` marker appears under the reply and `Option+←/→` switches the active candidate (and the context later turns build on) without calling the model again; the regenerate and switch keys are modifier-gated so plain typing in the composer never collides. Candidate selection persists across reload. File state switches with the candidate: leaving a candidate captures its on-disk post-state into an append-only `candidate-file-state` bundle chained off its content leaf (never re-captured once recorded, so a retried restore cannot mistake a half-restored disk for the candidate's true state), regenerate restores the fork baseline — the first-wins merge of every candidate's pre-turn checkpoint state — before the new candidate runs so it starts from the files the fork turn actually saw, and `Option+←/→` restores the target candidate's bundled files before re-pointing the selection marker (files move first because the restore is retryable while the marker is a one-shot flip). A failed or interrupted regenerate re-points the marker at the old candidate and restores its bundled files best-effort, capturing whatever the failed candidate left on disk as that candidate's bundle. Caveats: candidates created before this feature and never departed since have no bundle and switch conversation-only — such a switch records a degradation marker so a wrong file state can never be frozen as that candidate's bundle later, and regenerating over a bundle-less candidate (degraded or ledger-less fork turn) never moves files at all; host-process writes (`shell_exec` / `run_skill_script`, surfaced as taint warnings on switch) and the scratch root `tmp/` stay outside authoritative restoration guarantees, as with `/rewind`; Stage is unaffected (it writes no files); candidate switching is refused while a background SubAgent is running or queued. Old candidates are never deleted or garbage-collected, so the session file grows with use (documented in the bilingual user manual).

- **Bundled `update-config` Skill and `vesicle config` CLI surface.** A new first-party Skill guides configuration changes through validated, atomic CLI operations: inspect sanitized config state (`show`), modify providers/permissions/preferences/quality/settings (`set`, `add-provider`), manage non-secret `.env` structure (`env-set-empty`, `env-set-proxy`, `env-remove`), and validate all config files (`validate`). The provider-management surface now also supports per-field edits (`set providers providers.<id>.<field> <value>` for `protocol`, `baseUrl`, `apiKeyEnv`, `authMethod`, `responsesProfile`, `responsesTransport`, `userAgent`, and `defaultModel`), appending models (`add-model <id> --json`), removing models (`remove-model <id> <model>`), removing providers (`remove-provider <id>`), unsetting preferences/settings (`unset <file> <key>`), and warns on `.env` removal of a missing key. Structural/provider fields (`id`, `models`, `apiKey`) are rejected, and every registry write is pre-validated by re-parsing the serialized output before the atomic rename so a failed cross-field constraint never leaves a corrupted file. Secret values are structurally excluded — `.env` reads are whitelist-sanitized to `<set>`/`<empty>` markers with proxy credential masking, and no operation accepts a secret value as an argument; the Skill's `SKILL.md` instructs the model to guide users to edit `.env` manually for API keys, and to warn (without echoing, storing, or using) when a credential is pasted into the conversation. Two thin `.sh`/`.ps1` wrappers re-invoke the exact Vesicle runtime via the existing self-invocation contract, following the `skillify` pattern. A new `VESICLE_HOST_CONFIG_DIR` environment variable is injected into `run_skill_script` child processes alongside `VESICLE_SELF_EXECUTABLE`/`VESICLE_SELF_ENTRYPOINT`, so bundled scripts resolve the user-level config directory without re-deriving platform paths.

### Changed

- **Candidate file switching is now authoritative, and version-1 bundles are rejected (breaking).** Because full manifests snapshot everything under the content roots, manual edits and MCP-tool writes made while a candidate is active are captured when that candidate is left and deleted or restored like any other file on switch — they no longer survive switches untouched. Host-process taint warnings, symlink exemptions, and the scratch `tmp/` exemption are unchanged. Bundles recorded before this change (no `version` field) are rejected at parse: switching to such a candidate degrades to conversation-only with a status-bar notice and records a degradation marker, consistent with a bundle-less candidate. This is an alpha-stage breaking change with no migration path.

- **`Ctrl+B` is now the global candidate-tree shortcut and supersedes the composer's Emacs backward-char.** The binding sits at the same routing layer as the `Ctrl+O` page switch — after bottom-surface modals (an open panel keeps its keys) and above Workspace routing (both pages respond) — and uses the plain `0x02` control byte available in traditional VT terminals on Windows, macOS, and Linux. Bare `←` cursor movement and `Meta+b` word movement in the composer are unaffected.

- **`deepseek-subset-2026-07-31` now admits `deepseek-v4-pro` (#151).** DeepSeek's official Responses endpoint now serves both `deepseek-v4-flash` and `deepseek-v4-pro`, and the v4 Pro lane passed independent acceptance against `api.deepseek.com` on 2026-08-13 (plaintext reasoning, exact `call_id` function loop, usage/terminal/error semantics; `2` pass, `0` fail). The three fail-closed admission guards (registry loading, Guided Setup, adapter pre-network check), the conformance fixture, the bilingual provider reference, developer contracts, and the example registry now accept the documented pair while continuing to reject every other model; no new capability (WebSocket, `previous_response_id`, Conversations, storage, background, remote compact) is unlocked, and DeepSeek's server-side built-in `web_search` tool remains explicitly out of scope (#209). The example registry's `deepseek-responses` `baseUrl` is corrected to `https://api.deepseek.com/v1`, the path the official endpoint actually serves.

- **Bundled Harness updated to `prism-engine-v10@10.2.1` (Vesicle-side zero change).** The verified 73-file baseline (Neural Narratology Release `harness-20260812-1`, commit `979e0771`) adds a Transformation Directive (Outline optional chapter-level fields plus a Scene Allocation Transform column; standalone Weaver Phase 1/2 reads and self-checks it, orchestrated Weaver-Orch writes the Scene Plan for Scene Writer to fulfil, and Chapter Reviewer dimension 3 audits landing), Register modulation (a Register column on Scene Allocations — 日常/悬疑/对峙/动作/序章/余韵 — with dialogue-design principles annotated per register), four new scene techniques for Weaver and Scene Writer (一动作干三件事 / 声音动作先于身份 / 间接出场 / 叙述者声音按张力调节), and a forward-moved physical-canon self-check that reuses the character card's Visual Cortex across Weaver Phase 2, Scene Writer step 5, and Chapter Reviewer dimension 4. Agent, binding, capability, `protocolVersion` (`v10.1-prompt-assembly`), the `vesicle-v1@1.1.0` host Adapter (byte-identical), the Driver Contract (refreshed only in its `version` field; no operations, resources, agents, or engines changed), and the Anti-AI-Flavor Rule Pack (0.4.0, 32 rules; detector/judge rule data unchanged, judge rules still 23) are all unchanged, so this is a content-only baseline bump with no Vesicle source change. The 73-file inventory is unchanged (9 files revised, 0 added, 0 removed); the static prompt-asset ledger is recomputed upstream and stays well under the 24000-character static budget. Verified with `vesicle assets verify` (`compatible=true`), the full deterministic suite, and `vesicle doctor`.

- **OpenAI Responses `openai-public` real-provider gate recorded as passed.** On 2026-08-11, the official `api.openai.com` endpoint passed the full `openai-public` acceptance suite with `gpt-5.6-luna` (`3` pass, `0` fail): an HTTP/SSE function loop with exact `call_id` replay and stateless native Items, a non-stream JSON round, a standalone `/responses/compact` returning exactly one encrypted compaction Item, and a public WebSocket continuation tool loop (the WebSocket test overwrites `fetch` to fail any silent HTTP downgrade, so a pass confirms real WebSocket use). This completes the four-piece gate and supersedes the earlier partial gateway evidence, in which the trusted `doro-gpt` relay had passed HTTP/SSE and a non-stream request but its standalone compact returned HTTP 503 and its WebSocket probe failed. `STATUS.md`, `docs/dev/OPENAI_RESPONSES_CONFORMANCE.md`, and the bilingual provider reference now state the gate as passed; the protocol remains `experimental` in the 1.0.0-alpha.9 snapshot and is slated to graduate to `released` in the next release. No source code changed — the `ResponsesProfile` type carries no experimental/tier flag, and the adapter already implemented all four pieces.

- **`codex-beta-2026-02-06` promoted to a documented first-class, transport-agnostic profile.** Formerly described as a "frozen fingerprint fixture" and locked to WebSocket, it now mirrors Codex's own transport policy: with `responsesTransport: websocket` it sends Codex's V2 beta wire shape (`openai-beta: responses_websockets=2026-02-06` header plus `stream: true`) and falls back to HTTPS/SSE on WebSocket exhaustion exactly as Codex does; with `responsesTransport: http` it uses the standard public HTTPS/SSE shape. The Codex V2 fingerprint applies only on the WebSocket path; the config gate that forced `responsesTransport: websocket` for this profile is removed. The pinned header value and `ResponsesApiRequest` field set are unchanged between the conformance-pinned Codex commit `8f00b9a0` and current `main` (`a9dee37f`, 421 commits ahead), so the fingerprint is current. Documented in the bilingual user manual and `docs/examples/providers.yaml`, relabeled by `vesicle doctor`, and covered by a new opt-in acceptance lane `test:acceptance:responses:codex-beta` (passed against `api.openai.com` with `gpt-5.6-luna` on 2026-08-11).

### Fixed

- **File-tool cold start and directory-query consistency (#205, #206).** File-capable Engine turns and fresh/summary SubAgents now receive a bounded logical Project State snapshot, while `list_directory({ path: "." })` exposes a safe virtual root for explicit discovery without revealing `.vesicle/`, package files, or other Host infrastructure. Project State is live Host prompt context rather than session identity or conversation history: in-process pauses reuse the frozen turn snapshot, while restarts and new top-level turns observe again. Read-tool schemas derive and enumerate the canonical roots, project-root Persistent Instructions identify themselves as Host-managed, and selected instruction envelopes explicitly say their content is already loaded. `stat_path` reports allowed missing paths as structured `not_found`; `list_directory` now uses one structured `full`/`names` contract for project roots and layered `assets/`, reports file/directory/other counts so true empty directories remain distinguishable in lightweight mode, honors file-vs-directory overlay shadowing, and bounds both entries and traversal. The overlapping model-visible `list_files` surface is retired from the alpha contract; the new Neural Narratology `prism-engine-v10@10.3.0-alpha.1` Harness pack exposes only the unified tool.

- **`codex-http-relay` accepts relays that strip optional fields from the terminal output.** Some Codex-serving relays (e.g. the trusted `doro-gpt` gateway) return a `response.completed` whose `output` Items omit optional or empty fields that the `response.output_item.done` stream still carries — Item envelope `id`/`status`/`phase` and content-part `annotations`/`logprobs`. The strict deep-equal terminal/item reconciliation rejected this as a mismatch and failed closed, breaking the relay. `reconcileRelayTerminal` now accepts the terminal when it is a recursive subset of the completed-Item stream (same semantic payload, fewer optional fields) and retains the fuller `output_item.done` Items for replay; genuine payload mismatches (different text, `call_id`, item type, length, and so on) still fail closed. Relay acceptance against `doro-gpt` (`gpt-5.6-luna`) is green again.

- **`codex-http-relay` no longer sends `service_tier`, restoring compatibility with relays that reject it.** The profile sent `service_tier: "auto"` on every request; relays such as `sssai` reject every OpenAI tier value (`auto`/`low`/`medium`) with HTTP 400. `codex-http-relay` — the maximum-compatibility tier — now omits `service_tier` so such relays work, while `openai-public` keeps the explicit `"auto"`. Verified by relay acceptance against `sssai` (`gpt-5.6-sol`); `doro-gpt` and `buzz` tolerate the omission.

- **Skill-script execution no longer depends on the free-form Shell gate.** `run_skill_script` now uses its own `skill_exec` permission class and is available for every non-Stage session with a non-empty Skill catalog, even when `permissions.yaml` keeps `shellExec: false`. MANUAL and INERTIA still ask before execution; the default MOMENTUM and process-scoped YOLO follow their normal auto-allow behavior. The selected script remains a fixed, inspectable Skill resource whose catalog-pinned content hash is rechecked immediately before execution, and it retains structured argv plus the existing Process Runtime environment filtering, timeout, output cap, cancellation, process-tree cleanup, and host-process checkpoint taint. Interpreter absence or resource drift still fails clearly without execution. `shell_exec` remains separately opt-in and retains its `arbitrary_exec` approval path. Legacy pending `run_skill_script` approvals recorded as `arbitrary_exec` migrate on resume. This restores the intended out-of-box `skillify` validate/publish flow without enabling a general Shell.

## [1.0.0-alpha.9] - 2026-08-09

### Added

- **`grep_files` output modes, context lines, and output budget.** `grep_files` gains two optional parameters: `outputMode` (`content` for match entries with text, `files_with_matches` for just file paths, `count` for per-file hit counts) and `contextLines` (0–10 lines of surrounding context per match in content mode). A host-side 32 KiB output-text ceiling in content mode acts as a safety valve alongside the existing `maxMatches` cap (50 default, 200 max). In `files_with_matches` and `count` modes, `maxMatches` limits the number of files returned. The per-line 500-character excerpt cap is unchanged.

- **Bundled `novel-outline-v3` first-party Skill.** A hierarchical novel-outline workflow Skill (volume → chapter → scene) joins `vesicle-docs` and `skillify` under `host-assets/skills/`. It teaches a text-first methodology — read all source material, maintain two living-document ledgers (character growth and world state), draft volume/chapter/scene outlines, allocate a per-chapter tension budget with closed-form checks (Σ scenes = chapter total), track foreshadow plant/resolve, and write back ledgers — as readable references without scripts or process capability. It complements the Harness 10.2.0 tension-budget system. Discoverable as a Host-scope Skill via `/skill` and `vesicle skills list`.

- **Opt-in MCP tool-output persistence (#137B, slice 1).** Set `mcpOutputPersistence: true` in `.vesicle/preferences.yaml` to persist every MCP tool call's text result and decoded images under `tmp/mcp-output/<sessionId>/` (text) and `.../blob/` (images, native format) as addressable files with tool- and argument-derived names. The inline result is unchanged — persistence is an additive, best-effort durable copy the model re-reads with `read_file`/`grep_files`/`view_image` instead of repeating an expensive or non-repeatable MCP call. Off by default; advertised through a system-prompt hint only for engines that have MCP tools. The `tmp/` checkpoint exclusion (slice 0) keeps these spills out of the rewind ledger. Auto-truncation and bounded `read_file` ship in slice 2 (below).

- **MCP output auto-truncation and bounded file reads (#137B, slice 2).** Adds the `mcpOutputAutoTruncate` sub-toggle (requires `mcpOutputPersistence`): when on, MCP text results at or above 32 KiB are delivered inline as a 4 KiB preview plus a reference to the persisted full copy, so a single large result can no longer dominate the next provider request. `read_file` gains optional `offsetBytes`/`maxBytes` for a bounded byte slice that never loads the whole file (suited to large persisted outputs and giant single-line payloads), and `grep_files` caps each match-line excerpt at 500 characters. Byte-based thresholds keep CJK and English bounded consistently. Both toggles round-trip through `/theme --persist`; auto-truncate reads as off unless persistence is also on.

- **Dual-era Streamable HTTP MCP tools compatibility (#174).** Vesicle now connects to MCP Servers using either the legacy `initialize` protocol (revisions `2024-10-07` through `2025-11-25`) or the modern `server/discover` protocol (revision `2026-07-28`), and one Vesicle process can hold both eras concurrently in a single tool Registry. Per-server `negotiation: legacy|modern|auto` controls the connection path independently; absent `negotiation` defaults to `legacy` with zero wire change. The official `@modelcontextprotocol/client@2` SDK owns wire negotiation, typed errors, and incremental Streamable HTTP behavior behind a thin Vesicle adapter; SDK types do not enter `core/`, providers, Engine profiles, permission runtime, or TUI rendering. Modern connections send per-request `_meta` envelopes and routing headers (`MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`), cancel by closing the SSE response stream, and never use `initialize`, `notifications/initialized`, or `Mcp-Session-Id`. Auto probes with `server/discover` and falls back to legacy only for authoritative legacy-only signals; auth (401/403), server failure (5xx), timeout, network error, and ambiguous responses never fall back. Both eras normalize into the existing `ToolDefinition`, `ToolCall`, `ToolResult`, permission, Engine-scope, alias, result-delivery, and session-event boundaries. The existing inline image path (#175) and secret hygiene are preserved. Setup-generated entries use `negotiation: auto`; existing YAML is never rewritten. Doctor displays per-server mode, era, revision, and failure kind; the sidebar shows a compact era suffix. Resource, audio, URL/link delivery (#177), `input_required` auto-fulfilment, `subscriptions/listen`, local stdio, classic HTTP+SSE, MCP prompts/resources APIs, and OAuth are not part of this delivery.

- **Typed MCP multimodal tool results (#175).** Streamable HTTP MCP calls now cross a protocol-neutral, untrusted result normalizer instead of flattening unknown `content` objects into text. Ordered text remains compatible, while valid inline PNG/JPEG/GIF/WebP `ImageContent` is strictly base64-decoded, checked against declared MIME and magic bytes, stored in the existing content-addressed attachment store, and materialized only for a vision-capable main or SubAgent provider request. Session JSONL, resume, and compact history retain only `source: "mcp"` references and host-derived labels. Non-vision models, MCP error results, malformed or mismatched images, attachment failures, and the provisional shared 20 MiB decoded-image ceiling degrade to bounded payload-free notices; resource, audio, URL/link, and unknown items remain explicitly unsupported and are never auto-fetched or injected.

### Changed

- **Bundled Harness updated to `prism-engine-v10@10.2.0` (Rule Pack 0.4.0).** The verified 73-file baseline (Neural Narratology Release `harness-20260808-1`, commit `90f3488`) adds a per-chapter tension budget with Scene Allocation closed-form checks, an optional volume-level planning layer, dialogue-writing guidance injected into Scene Writer and Weaver, a Scene Writer pre-writing five-element checklist, a new Evaluate dimension H (setting-reveal balance), and Anti-AI-Flavor Rule Pack 0.3.0-alpha.4 → 0.4.0 with three new zh-CN detections: `zh-f1-negative-description`, `zh-f1-decorative-ending`, and `zh-f3-period-density` (F3, observe-only). The Harness Driver Contract and required Vesicle capabilities are unchanged (the contract diff is version-only). The new `zh-f3-period-density` rule uses a `period_per_100_chars` metric signal, so Vesicle adds host-side support for that signal — dialogue-excluded `。` density per 100 characters, gated by `minimumMatches` — alongside the existing `em_dash_per_100_chars` path; the Quality Guard loader and detector mirror the em-dash special case and do not require rule `patterns` for this signal. The bundled calibration corpus stays at 24 host-conformance cases; the judge rule count rises from 21 to 23.

- **Scratch root `tmp/` excluded from rewind checkpoints (#137B, slice 0).** Guarded file mutations under the project-relative scratch root `tmp/` remain writable through ordinary file tools, but are now excluded from the per-turn file checkpoint and rewind lifecycle: `/rewind` and double-Esc no longer restore `tmp/` state, so scratch edits (including `tmp/skillify/` drafts) are not rewind-safe. This reverses the 137A decision and prepares `tmp/` to hold ephemeral MCP tool-result spills without polluting the durable content-root checkpoint ledger. The host still never auto-cleans scratch state. Moves across the `tmp/` boundary are not fully reversible on rewind (scratch→content loses the moved body; content→scratch leaves a duplicate in `tmp/`); use `copy_file` to promote scratch work when rewind-safety matters.

### Fixed

- **Skill tools moved to host-layer injection, restoring the Skill surface after the Harness 10.2.0 bump.** The bundled Harness 10.2.0 upgrade (`f964c41`) replaced `assets/engines/` wholesale and silently dropped the three Skill tools (`activate_skill`, `read_skill_resource`, `run_skill_script`) from every non-Stage engine profile's `defaultTools`. Because the runtime gated the entire Skill surface on `profile.defaultTools.includes("activate_skill")`, real sessions lost the `<skill_catalog>` prompt block, all Skill tools, and existing activations were pruned — making every Skill (including the bundled `novel-outline-v3`, `vesicle-docs`, and `skillify`) undiscoverable and unusable. Integration tests did not catch this because their fixture wrote a synthetic profile that re-added the tools. The Skill tools are now injected by the host layer for every non-Stage engine when the session catalog is non-empty, independent of the Harness profile's `defaultTools`, so harness bumps can no longer clobber them. `resolveEngineEligibleCatalog` now gates only on `profile.id === "stage"`. A `VESICLE_HOST_ASSETS_DIR` environment variable lets custom deployments resolve the host-assets root independently of the bundled package layout.

- **Light-theme text selection and Workspace editor contrast (#158).** Selectable TUI text now receives one theme-owned foreground/background selection pair instead of relying on OpenTUI's implicit transparent-buffer color swap. Markdown propagates the same pair through prose, list markers, fenced code, and tables, including mounted selections during theme changes. The Workspace textarea now explicitly follows the active theme for ordinary and focused text, cursor, and selection colors, fixing its white-on-light editor text.

## [1.0.0-alpha.8] - 2026-08-01

### Added

- **Host-bundled `skillify` Skill and scratch-first draft publication (#127).** A user can ask Vesicle to turn a proven workflow from the current conversation into a reusable portable Skill without hand-authoring a directory. The bundled `skillify` Skill extracts the reusable process into `tmp/skillify/<name>/` using ordinary guarded file tools, validates the complete draft through the existing parser and bundle rules, and publishes create-only to `.agents/skills/<name>/` (project) or the immutable Skill Store (installed) after an explicit target decision. Publication is create-only: no overwrite, merge, upgrade, or backup-and-replace. Drafts are always retained; the current session catalog is never mutated, and the published Skill is discoverable only from a new session. Two thin `.sh`/`.ps1` wrappers relay a versioned JSON contract (`vesicle.skill-draft/v1`) from a non-model-visible CLI (`vesicle skills validate --draft --json`, `vesicle skills publish-draft --target <project|installed> --json`); the wrappers contain no path, hash, copy, staging, or cleanup logic. Generic runtime support shipped with this feature: `.ps1` script execution in `run_skill_script` (PowerShell 7 preferred, Windows PowerShell 5.1 fallback on Windows, `pwsh`-only elsewhere, `-File` argv without `-Command` or `-ExecutionPolicy Bypass`); stable self-invocation (`VESICLE_SELF_EXECUTABLE`/`VESICLE_SELF_ENTRYPOINT`) so bundled scripts invoke the exact Vesicle runtime that launched them without PATH assumptions, injected into the filtered `run_skill_script` child only; a shared portable bundle inspection seam (`src/skills/bundle.ts`); and a guarded draft publisher with linked-ancestor rejection and sibling-staging atomic project publication (`src/core/skills/draft-publisher.ts`). Ordinary `skills install|update|rollback|uninstall` semantics are unchanged.

- **Project-relative `tmp/` scratch root (#137A).** Ordinary guarded file tools can now read and mutate paths under project-relative `<project>/tmp/` for drafts and intermediate work, and `tmp/` is root-anchored in `.gitignore`. Scratch mutations participate in the existing per-turn file checkpoint and rewind lifecycle; absolute OS `/tmp`, `..` escapes, and symbolic-link traversal remain rejected, and the fixed-root rule still refuses create/move/delete of `tmp` itself. `tmp/` is deliberately excluded from `/init` scanning, Stage input discovery and source-drift checks, Artifact Workbench `/artifact` and `/validate`, Output Quality Guard artifact targets, `vesicle skills copy-template` destinations, and automatic publication; the host never auto-creates or auto-cleans scratch state. The root taxonomy moved from `core/artifacts/roots.ts` to the neutral `core/project/roots.ts` (`sourceRoots`, `artifactRoots`, `scratchRoots`, `projectContentRoots`, `modelWritableRoots`), and the runtime prompt, public developer docs, paired user manual, `README` pair, and `STATUS` describe the source/artifact/scratch distinction.

- **Optional provider HTTP/WebSocket proxy (#150).** One optional `VESICLE_PROVIDER_PROXY` in the user-level `.env` beside `providers.yaml` routes all provider HTTP(S) and WebSocket traffic through a supported `http://`/`https://` proxy, with URL userinfo as the Basic-auth mechanism. Precedence is user-file → process → inherited terminal proxy variables → direct, with a blank value absent rather than "direct"; an explicit Vesicle proxy overrides inherited variables and is not bypassed by terminal `NO_PROXY`. The shared provider fetch boundary and the native Responses WebSocket factory use Bun's native `proxy` option, preserving every existing retry, cancellation, streaming, continuation, rotation, and WebSocket-to-HTTP fallback rule. Proxy `407` is terminal and non-retried on both HTTP and WebSocket (a per-session preflight raises it before the WebSocket retry loop, since native WebSocket otherwise surfaces a proxy 407 as a generic connection failure); proxy connection failures follow the existing retry policy; the proxy URL, host, port, and credentials never enter error messages, causes, diagnostics, session/quality artifacts, or `vesicle doctor` output. Guided Setup model discovery also routes through the explicit proxy so proxy-only networks can complete onboarding. Deterministic resolver/redaction coverage, real local CONNECT-boundary tests for HTTPS and native WebSocket (including a WebSocket bad-credentials regression), and the official OpenAI HTTP and native WebSocket function loops through a required proxy (passed on 2026-07-31 with `gpt-5.6-luna`, sanitized evidence) now all pass; the official acceptance is opt-in, injects the resolved proxy policy, and reports unavailable when its prerequisites are absent. (Closes #86.)
- **`--dark` / `--light` launch flags.** Long-only, process-scoped initial theme preferences on the typed startup parser. Repeating the same flag is idempotent; supplying both is an explicit parser error; a top-level `--` ends recognition so a following flag is a literal operand. ### Added

- **Persistent Instructions.** User-authored Markdown that customizes an Engine's workflow and survives new sessions — the host loads it into the system prompt automatically, so there is no need to ask the model to write a spec to a file and remind it to read it next session. Files live at two scopes, both using the same names: `VESICLE.md` (general, every Engine) and `VESICLE.<engine>.md` (Engine-specific override) at the project root for project scope, and the same names beside `providers.yaml` for user scope, which applies across every project root. Within one scope an Engine-specific file replaces the general file; across scopes the user file is followed by the project file, and project content wins on a direct conflict. Instructions are appended after the byte-identical Engine prompt as host context — the Engine contract stays the single system authority and the stable prefix-cache prefix — and can only customize work within existing host capabilities; they cannot add tools, permissions, gates, validators, or filesystem authority. Selection is resolved from current disk when a top-level turn begins, when a session resumes after a process restart, and on a confirmed Engine switch; within a single turn the selection is frozen so a mid-turn pause and resume observes one stable instruction set, and an edit takes effect on the next turn. An invalid, linked, or oversized scope is skipped with a warning while the turn continues, and the combined selected content is bounded to 32 KiB. `vesicle prompt shape` / `prompt dump --engine <id>` and the `/instructions` command show the effective selection, provenance, byte budget, and diagnostics.
- **`vesicle --version` / `-v` and `--help` / `-h`.** A typed startup parser now classifies one invocation into a terminal action (`--version`/`-v`, `--help`/`-h`), a subcommand, or a project launch. `--version` prints the package version baked into the binary at build time; `--help` prints the global usage. Short options bundle (`-vh`), `--` ends option parsing so dash-prefixed paths work, and `--dangerously-skip-permissions` remains a position-agnostic process flag. Queued messages steer the active loop after its current complete tool round and before the next provider request. Every slash command now declares a required busy-turn behavior in the command registry: safe host-only commands run immediately, artifact reads wait for the current tool round, and configuration, picker, or session commands wait for the Agent Loop. - **OpenAI-compatible Chat Completions SSE streaming** — assistant content deltas and streamed `tool_calls` reconstructed into the same final response shape used by non-streaming calls, plus agent-loop streaming events and TUI live assistant-draft rendering while a response is in flight.
- **Thinking blocks and reasoning visibility** — provider-neutral internal thinking blocks with OpenAI-compatible `reasoning_content` as a compatibility bridge, preserved through streaming, tool-loop follow-ups, and session resume. `/effort off|low|medium|high|xhigh|max` controls runtime thinking effort (plus `/effort auto`/`unset` to clear), and `/reasoning hidden|collapsed|expanded` controls display with bounded collapsed/expanded tail views.
- **Model config defaults** — object model entries in user-level `providers.yaml` for `generation` (`temperature`, `maxTokens`) and `capabilities` / `limits` metadata, while preserving existing string model entries.
- **Filesystem tool v2** — `stat_path`, `grep_files`, ranged `read_file`, vision-gated `view_image`, `create_file`, `replace_in_file`, `append_file`, `delete_file`, `copy_file`, and `move_file`, all behind the existing project-relative path guards and artifact-root write boundaries.
- **File operation ledger** — successful filesystem tools now emit structured `fileEvent` metadata through agent-loop activity events and session JSONL tool records.
- **Multimodal image input** across OpenAI-compatible Chat, Anthropic Messages, and Gemini. Models opt in with `capabilities.vision: true`; the TUI accepts clipboard images with `Alt+V` (and WSL-compatible `Ctrl+Alt+V`), keeps atomic `[Image #N]` elements through history/rewind/resume, and stores bytes in a content-addressed `.vesicle/attachments/` store with base64 only on the in-memory provider request copy.
- **Streamable HTTP MCP integration** — optional user-level `mcp.yaml` beside `providers.yaml` declares enabled servers, `${ENV_VAR}` header expansion from the sibling `.env`, tool prefixes, include/exclude filters, engine scoping, and timeouts. Discovered tools expose as `mcp_<prefix>_<tool>` aliases, execute through `tools/call`, surface structured `mcpEvent` metadata, appear in prompt dumps, and are reported by `vesicle doctor` without printing secret header values. The Workspace sidebar shows a compact MCP status section.
- **Tavily-backed web tools** (`web_search`, `web_fetch`, `web_map`, `web_crawl`, `web_research`) for ETL and Evaluate turns, reading `TAVILY_API_KEY` from the user-level `.env` or process environment and persisting structured `webEvent` metadata.
- **Rewind and per-turn checkpoints** — `/rewind` (alias `/checkpoint`) and empty-input double Esc open one selector that can restore conversation, file checkpoints, both together, or summarize from a selected prompt, forking future turns while preserving abandoned branches in append-only session JSONL. Per-user-turn checkpoints live under `.vesicle/file-history/` with pre-mutation backups, changed-file and insertion/deletion previews, a 100-snapshot active limit, and branch-aware resume.
- **Engine switching** — `/engine [id]` for manual Prism engine inspection and switching, plus the `request_engine_switch` model-visible handoff tool that pauses for confirmation and switches only future turns after the user confirms. Both share one unified transition record; confirmed switches append a bounded user-role `engine_handoff` packet so OpenAI-compatible, Anthropic Messages, and Gemini adapters all receive the same target-engine context without mutating the dynamic system prompt.
- **`ask_user_question`** model-visible clarification tool — one single-select question with 2-4 model options plus host-owned Skip and open-ended answer fallbacks, keeping question-panel arrow-key selection from scrolling the message history and resuming the current engine loop after selection.
- **`/compact [notes]`** summarizes the active session through the configured provider and replaces old context with a user-role summary on a new append-only branch. `/engine <id> --summary [notes]` compacts first then switches; model-requested handoffs now also offer `Confirm with summary`.
- **Cross-provider usage normalization** — provider responses normalize runtime usage metadata across all three adapters. The TUI footer shows compact logical-turn upstream/downstream token totals, cached-input hits, and context-window percentage when configured, plus session totals that add logical-turn summaries instead of re-counting repeated context sends; sessions persist the underlying telemetry as host-only metadata. `/context` reports configured limits, latest occupancy, session totals, and auto-compact metadata without calling the provider.
- **Provider/model registry and artifact workbench** — a user-level `providers.yaml` declares multiple providers and models plus an optional `defaultModel`, and the TUI offers a two-step `/model` picker, provider-default shortcuts, and exact provider/model selection. `/artifact [n|path]` lists or previews generated files as bounded structure-preserving cards, and `/validate` checks the selected file on disk.
- **Provider cancellation** via `AbortSignal` for OpenAI-compatible, Anthropic Messages, and Gemini requests; Esc during generation interrupts the request and restores the submitted prompt for editing.
- **Slash-command candidate menu** — a filtered popup while typing a command token, with Up/Down or Ctrl+P/Ctrl+N selection, Tab/Enter completion, and Escape cancellation. `/model`, `/engine`, `/effort`, and `/reasoning` complete their arguments, including alias matching that completes to canonical values.
- **Standalone executables** — `bun run build:exe` cross-compiles a Windows PE (`prism-vesicle.exe`) and a host ELF (`prism-vesicle`) from WSL in one run, embedding OpenTUI's tree-sitter worker as a flat Bun worker entrypoint so no external `node_modules/` runtime bundle is needed. The compiled binary loads its immutable default `assets/` beside `process.execPath`. `vesicle debug markdown-runtime` verifies the worker, WASM runtime, and highlight probes without starting the TUI; `bun run build:assets` creates the separately distributed editable `dist/prism-vesicle-assets.zip` release pack.
- **GitHub Actions CI** validates Linux ELF and native Windows PE release shapes, including the standalone Markdown runtime diagnostic and external assets; pull-request runs upload short-lived versioned artifacts for review without publishing a GitHub Release or npm package.
- **Protocol-specific outbound header profiles** aligned with audited OpenCode Chat Completions, Claude Code Messages, and Gemini CLI behavior. Vesicle emits a branded `User-Agent` derived from `package.json` and the active Bun runtime, supports an optional provider-level `userAgent` override, preserves protocol-native streaming `Accept` behavior, and updates the Anthropic Stainless retry counter on each transport attempt.
- **Provider retry** — pre-response network failures, HTTP 408/429, and 5xx responses retry up to two times with bounded exponential backoff, jitter, and `Retry-After` support across all three adapters. Cancellation interrupts backoff immediately; partially consumed SSE streams are never replayed implicitly.
- **"Synaptic Prism" TUI rewrite (phases A–E)** — a deep cool surface with a single emerald prism accent; a per-role spectrum lane on each message with asymmetric containment; inline filesystem tool-call cards with real line-level diffs and structured outcome footers; a per-turn `▣ {engine}·{model}` marker with per-engine accent colors; a stream-first single-sidebar layout; live turn-phase status tracking; an `engineDisplayName` helper (etl → ETL, runtime → Runtime, weaver-orch → Weaver-Orch); and a `scripts/palette.ts` dev swatch utility.
- **Host-owned multiline composer** replacing OpenTUI's single-line input — soft-wraps long continuous input, expands the bottom area by visual line count, keeps a cursor-following viewport, and lets Up/Down move through wrapped rows before falling back to prompt history. Plain Enter submits, `Ctrl+Enter` inserts newlines, `Shift+Enter` is inert when reported distinctly, and trailing backslash+Enter remains a compatibility newline fallback.

### Changed

- **Shared Markdown display layer** conservatively converts common LaTeX formulas to terminal-readable Unicode and downgrades common Markdown extension syntax (`==mark==`, `~sub~` / `^sup^`, footnotes, definition lists, image alt text, emoji shortcodes, and common inline HTML such as `<u>`, `<mark>`, `<kbd>`, `<abbr>`, `<details>`) into readable terminal text outside fenced code blocks. Artifact previews strip common Markdown markers, and the shared TUI syntax style registers Prism-toned Markdown/code token colours.
- **Session records** now carry `uuid` and `parentUuid`, allowing append-only conversation forks; existing linear JSONL sessions receive deterministic implicit parents when loaded and remain resumable.
- **Escape follows the Claude Code prompt contract** — single empty Escape is a no-op, empty-input double Escape opens rewind, and non-empty double Escape saves then clears the draft; Ctrl+Q and the existing double Ctrl+C path remain explicit exit controls.
- **`AGENTS.md` and `CLAUDE.md`** expanded into full AI-collaborator entry points that link the repo's workflow, style, status, contribution, provider config, verification, and documentation-sweep rules.
- **Rapid-development workflow exception** treats `develop` as the active trunk for low-risk internal iteration while preserving PR/CR flow for high-risk or release-bound work.
- **OpenAI-compatible provider backend split** into request shaping, response parsing, streaming, wire types, and structured provider errors to harden the transport foundation.
- **Provider configuration requires the user-level `providers.yaml`** — Vesicle no longer falls back to a single `VESICLE_API_KEY` environment configuration when that file is missing. API keys load from the `.env` beside it, which takes precedence over inherited process variables so legacy project-root `.env` files cannot mask it; `vesicle doctor` reports whether that `.env` was found, without printing secret values.
- **Thinking-tier mapping** sends provider wire controls (`off` disables; `low`/`medium`/`high` map to high effort; `xhigh`/`max` map to max effort); unset sessions keep the provider/model default and send no thinking control fields. Generation defaults come from the selected model config instead of a hardcoded adapter temperature.
- **Provider configuration accepts `anthropic-messages`** (with optional `authMethod: x-api-key` or `bearer`) and **`gemini-generate-content`** (with `authMethod: x-goog-api-key`).
- **Shape-near singular/plural command pairs consolidated** — `/artifact` and `/engine` list without arguments and act with a target; redundant `/artifacts` and `/engines` are removed. `/effort` is now the thinking-control command, separated from `/reasoning` display; the old name and the hidden `/workflow` alias for `/engine` are removed, leaving `workflow` available for a future guided-workflow feature.
- **Public alpha documentation boundary declared**: setup, diagnostics, prompt shape inspection, and bundled examples are the supported onboarding path; comprehensive user documentation is intentionally deferred while feature and fix work remains the priority. The root README was reorganized into a concise installation and onboarding entry point with the detailed implementation inventory moved behind `STATUS.md`, natural line wrapping established as the Markdown prose convention, and synchronized Simplified Chinese editions of the README and contribution guide added.
- **npm/Bun package renamed** from the unowned scoped candidate `@prism/vesicle` to the available public package name `prism-vesicle`. The 1.0.0-alpha.1 release contract makes deterministic tests no longer run a real provider merely because local credentials exist, ships npm packages with only runtime files and pinned dependencies, resolves package assets and the OpenTUI worker independently of the caller's cwd, and adds `vesicle assets init` to create an editable project-local asset copy.

### Fixed

- **`source_materials/`** is now a writable project root for model-generated research and web captures; `/artifact` remains scoped to the four final-output roots.
- **`/artifact <n|path>`** renders the selected file in the message stream; the former implementation only wrote an unconsumed selection signal and claimed the preview was visible in a right-hand pane that had already been removed.
- **Sidebar artifact numbering** follows the fixed root order (`workspace`, `novels`, `reports`, `test_runs`) with newest files first inside each root, and the section scrolls within the remaining sidebar height instead of silently dropping entries after the first eight.
- **Non-confirm gate and question routes** type and paste into their always-visible Reject / freeform composer through one shared activation predicate across rendering, keyboard, and paste routing, preventing drift.
- **Non-confirmed `request_engine_switch`** decisions return their tool result to the provider and continue under the current engine; confirmed handoffs still switch only future turns without calling the provider under a new system prompt.
- **Slash-command candidate selection** renders reactively, resets when the filter query changes, and remains valid for empty result sets, so arrow keys move exactly one visible cursor.
- **Provider/model pickers** participate in bottom-layout sizing and cap visible rows to terminal height instead of overwriting the composer or telemetry footer; invalid `defaultModel` references are rejected while loading configuration, and `/model <model>` stays backward-compatible with active-provider switching.
- **Prompt contracts** align user-choice checkpoints with the current `ask_user_question` runtime, bind the Runtime engine's `runtime-turn` stop gate to `request_confirmation`, and keep RooCode-era mismatched tool names such as `ask_followup_questions` and `apply_diff` out of bundled prompts.
- **`vesicle prompt dump` / `prompt shape`** report the effective model-visible tool surface, including runtime-added `ask_user_question`, `request_engine_switch`, and stop-gate-only `request_confirmation`.
- **Windows Ctrl+C selection copying** writes clipboard text through a UTF-8 base64 bridge before `Set-Clipboard`, avoiding mojibake when copying Chinese or other non-ASCII text.
- **TUI tool calls and results** render as compact transcript summaries instead of dumping full tool arguments or full file contents into the main chat stream.
- **Streaming** rejects premature SSE EOF, reports malformed chunks with a provider-stream error, retries without OpenAI-specific `stream_options` for stricter compatible providers, and preserves the final assistant turn in the in-memory conversation history.
- **OpenAI-compatible streamed tool-call names** keep the latest provider value instead of concatenating repeated `function.name` deltas, avoiding duplicated names from non-conformant streams.
- **OpenAI-compatible reasoning responses** preserve provider `reasoning_content` through non-streaming, streaming, tool-loop follow-up requests, and session resume so reasoning models can use tools without losing required thinking context.
- **`/model` and session resume** resolve API-key availability through the user-level provider `.env`, so they no longer show "API key: missing" when the selected key is stored there.
- **Source and compiled startup** use separate OpenTUI setup paths: `bun run dev` preloads OpenTUI before importing the TUI, while `build:exe` applies the OpenTUI Bun build plugin explicitly, avoids external `bunfig.toml` preload lookup, and resolves compiled runtime files without changing the project cwd.
- **`bun run build:exe`** succeeds on Linux/macOS — the compile step emits the entry basename with a platform-appropriate extension, so the post-build rename no longer fails looking for a nonexistent `main.exe` and produces a host-native `prism-vesicle` binary outside Windows.
- **Standalone binaries preserve the launch directory as project root**; sessions, workspaces, and project asset overrides stay with the active project while runtime/default files resolve explicitly beside the executable. The embedded tree-sitter worker is now used even when the build directory's `node_modules/` remains reachable, preventing that development-only path from overriding the single-file runtime.
- **npm/Bun installs expose `vesicle` through an `.mjs` Bun launcher** that npm 11 retains during publication.
- **Rewind confirmation panels** with file changes reserve enough bottom layout height for the `Never mind` option, manual-edit warning, and footer. Inline freeform question composers and gate note/reject composers likewise reserve bounded layout rows to prevent option, input, and footer overlap in short terminals.
- **Composer-owned arrow keys** consume their original OpenTUI event before renderable dispatch, so cursor movement and prompt-history recall cannot also scroll the message stream or sidebar; modified arrows are consumed as composer no-ops when they have no composer action, and `Ctrl+C` consumes immediately while preserving its copy-selection / double-press exit contract.

## [0.1.0] - 2026-07-07

### Added

- Engine profile loader: `assets/engines/*.yaml` now drives systemPrompt composition, tool resolution, validator names, and declared stop gates at runtime. A hand-written YAML parser handles the narrow profile schema with no dependency. Profiles that name unknown tools or omit required fields fail loudly.
- Stop-gate runtime: the `request_confirmation` tool lets the model pause the workflow for user confirmation. The agent loop returns a `needs_user` result; `resolveGate()` feeds the decision back and continues. Undeclared gates are refused, not paused. ETL Phase 0 blueprint confirmation is wired end-to-end.
- Module A and Module B validators: v9 schema checks for character cards (frontmatter field allowlist, seven sections, Persona Topology subsections, Invariant/Variant axis counts, positive-shift direction, L-System leakage) and scenario cards (3–5 beat map, per-beat fields, tension range, non-monotonic trajectory, legacy field rejection).
- `vesicle prompt dump --engine <id>` and `vesicle prompt shape --engine <id>` print the fully composed system prompt and profile structure for "is there host pollution?" auditing.
- Session resume: `listSessions()` and `loadSessionMessages()` reconstruct prior turns. The TUI `/resume`, `/resume <n|id>`, `/new`, and `/help` commands manage sessions without hitting the provider.
- Markdown rendering in the TUI: assistant messages render through OpenTUI's `<markdown>` component with `conceal`, so headings, lists, emphasis, and code spans display as formatted output.
- Select-style gate UI borrowing Claude Code's PermissionPrompt shape: numbered Confirm/Reject options, Tab to expand confirm notes, and a persistent reject/discussion escape hatch.
- Centralised colour palette and shared syntax style in `src/tui/theme.ts`.

### Changed

- ETL stop gates now include `phase-confirmation` in addition to `blueprint-confirmation`, so Phase 1/2 artifact checkpoints use the `request_confirmation` tool instead of plain prose pauses.
- The TUI shell is now responsive: narrow terminals use a readable single message column, medium terminals add a workspace/artifact sidebar, and wide terminals add the activity/artifact pane.
- `/resume` now opens a TUI session picker, and sessions paused at an unresolved `request_confirmation` gate can be resumed back into the gate panel. Resumed sessions now load prior visible conversation into the message stream.
- ETL validators no longer run on ordinary assistant prose; they run only on artifact-shaped YAML-frontmatter assistant output.
- Wide TUI layouts now use the right pane for activity and recent artifacts instead of repeating the last assistant output.
- The agent loop emits coarse activity events for provider requests, assistant responses, tool calls, gate pauses, and validation.
- The input area now shows slash-command hints and supports Up/Down prompt history recall.
- Agent-loop tool ceiling raised 6 → 40 with a no-progress circuit breaker (4 consecutive failing-tool rounds stop the loop and persist the last response instead of throwing). Vesicle's controlled file tools do not need the strict caps a coding-agent host would impose.
- `RunPromptResult` is now a discriminated union (`complete` | `needs_user`) with an optional `validation` outcome on the complete branch.
- ETL engine prompt Phase 0 now instructs an explicit `request_confirmation` call instead of prose "wait for user confirmation"; a new Stop Gate contract section documents all gated vs conversation-bound points.
- Validator outcomes surface in the TUI message stream and session log; failures are advisory and never abort a turn.

### Fixed

- Gate confirmation now renders in a dedicated bottom panel with bounded summary text, stable option rows, and no side-panel squeezing at gate time.
- Runtime artifact roots (`workspace/`, `test_runs/`, `novels/`, `reports/`, `source_materials/`) are now gitignored with `.gitkeep` stubs, so model/user output does not enter git history.
